# GSC 无人机集群地面站 · 测试用例文档

> 依据 `docs/` 下各模块 PRD（态势大屏 V2.1、单机操控 V2.1、告警 V2.1.1、目标列表 V2.1、任务管理 V2.0、设备展示 V1.0）与 `docs/websocket-api.md` 契约编写，覆盖前端各功能模块。
> 用例设计方法：等价类划分、边界值分析、场景法、状态迁移法、异常推测法。

## 一、文档说明

### 1.1 用例字段说明

| 字段 | 说明 |
| --- | --- |
| 用例编号 | 唯一标识，格式 `TC-<模块>-<序号>` |
| 优先级 | P0（冒烟/核心链路）、P1（重要功能）、P2（一般/边界/体验） |
| 前置条件 | 执行用例前必须满足的环境与数据状态 |
| 测试步骤 | 操作序列 |
| 预期结果 | 可观测的验收断言 |
| 关联需求 | PRD 需求编号 |

### 1.2 通用测试环境

- 前端：`npm run dev`（Vite，`http://localhost:5173`），后端 `192.168.120.30:8080`（或本地 Mock WS 服务）
- 浏览器：地面站指定 PC 客户端环境（Chrome 最新版），分辨率 1920×1080
- 工具：WS Mock 工具（可按 `docs/websocket-api.md` 信封格式注入消息）、DevTools Network/Console（过滤 `[ws]`/`[realtime]`/`[ws-log]`）
- 账号：有效操作员账号 1 个；测试设备若干（含 在线待命 / 任务中 / 离线 / 低电量 / 故障 状态各至少 1 台）

### 1.3 通用断言（全局规范，各模块用例不再重复）

- 失败 toast 红色、成功 toast 绿色，停留约 2~3s 自动消失（任务管理约定 3s）
- 所有网络请求失败必须有 toast/弹窗，禁止静默失败
- 全局 Esc 键可退出聚焦视图或关闭当前弹窗
- 后端接口异常时页面不崩溃、不白屏，保留已有数据
