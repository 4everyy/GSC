# 功能背景

随着无人机在巡检、测绘等场景的普及，现有操控系统存在交互效率低、状态反馈模糊等问题，导致用户操作失误率上升。本项目旨在设计设备操控模块，通过标准化交互逻辑、明确状态边界，提升操控安全性与易用性。

# 术语定义

RTK固定解：无人机通过RTK（实时动态差分）技术实现厘米级定位的状态。

禁飞区：系统预设的禁止无人机进入的地理区域（如机场、军事区），触发时自动拦截起飞/航线指令。

滑动确认框：交互组件，需用户滑动滑块完成二次确认，防止误触关键指令。（支持取消）

本规范适用于文档中所有飞行控制及多机协同功能模块，各具体功能点需严格遵循以下全局约定。

# 三、全局通用交互与状态规范

3.1 全局反馈机制 (Toast )

轻量级提示 (Toast)：用于常规操作的成功反馈、错误提示、执行时的状态变化。例如：指令下发成功 → toast状态流转为 “任务中” ， 指令下发失败 → 设备保持原状态，toast报具体错误。

触发时机：指令成功下发（如“起飞指令已发送”、“返航指令已发送”）,指令执行完毕，指令异常。

展示规则：屏幕居中偏上显示，2秒后自动消失，不打断用户当前操作，每辆飞机的状态变化及时用toast提醒。

对无法执行该操作的飞机实行：飞机在执行任务中时，不允许执行其余操作（一期暂定逻辑），态势图上点击时出现toast提醒“正在起飞中”，在设备管理面板中该设备的复选框置灰，不可选，防止重复执行操作。

3.2 按钮状态与防呆设计 (UI State)

动态置灰 (Disable)：当飞机状态不满足前置条件时（如：离线），相关操作按钮必须置灰且不可点击。

防连点 (Debounce)：所有核心指令按钮（起飞、降落、返航等）在点击后，需立即进入 Loading 或 Disabled 状态，直到收到飞控的明确反馈（成功或失败）后，才恢复可点击状态。严禁连续下发相同指令。

状态互斥：处于“任务执行中”时，部分冲突的指令按钮应置灰或隐藏。

3.3 全局安全与校验逻辑 (Safety & Validation)

隐式解锁 (Auto-Arm)：当用户在“锁定”状态下点击需要动力的指令（如起飞、航点飞行）时，系统底层自动执行“解锁”逻辑。若解锁失败，需中断后续任务并弹出具体错误提示。

全局中断优先级：当多个指令冲突时，遵循以下优先级：紧急停止/迫降 > 返航 > 降落 > 悬停 > 常规任务。高优先级指令可直接打断低优先级任务。

3.4 异常与断连处理 (Failsafe)

指令下发失败：若因网络或通信原因导致指令未到达飞机，系统需捕获异常并提示“指令下发失败，请检查链路”。

执行中断连：若飞机在执行任务过程中突然“离线”，地面站需立即将该飞机状态变更为“离线/失联”，并在地图上保留其最后已知位置，同时触发系统级的失联保护策略（如自动返航或原地悬停）。

3.5 坐标系与单位规范 (Data Standard)

高度基准：本文档中所有涉及的高度（H / Alt）参数，若无特殊说明，均指相对起飞点（Home点）的相对高度，单位为米 (m)。

3.6 设备状态 (DEV STS)

设备状态需要在线，且在待命中才能下发操作指令。

执行操作的最后一步：点击“确认”时，系统后台需再次校验所有选中飞机的实时状态，若此时有飞机掉线、任务中，需提示“部分飞机状态异常，请重新选择”。

参数设置面板中信息未填写完整，航迹生成按钮，确认按钮均无效。（toast报错提醒或其余醒目提示）

取消功能：点击取消后，在该功能点下对地图进行的操作被清除，面板数据被清空且关闭。

选择设备：设备选择可以与态势图联动，可以直接在地图上选择执行飞机。
