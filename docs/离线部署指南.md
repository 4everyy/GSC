# 离线地图部署指南（方案 A - MapLibre + tileserver-gl）

## 概述

本指南说明如何在内网（无互联网）环境下部署本地矢量瓦片服务，让 MapLibre 地图完全离线运行。

## 架构

```
浏览器 (GCS 前端)
    │
    │ HTTP 请求 Style JSON + Vector Tiles (.pbf) + Glyphs (.pbf)
    ▼
tileserver-gl (Docker, 端口 8081)
    │
    ├── data/suzhou.mbtiles    ← 矢量瓦片数据
    ├── styles/dark/style.json ← 暗色样式定义
    └── fonts/                 ← 中文字体切片
```

## 前置条件

- **Docker Desktop**（Windows 11）已安装并运行
- **网络连接**（仅首次准备数据/字体时需要）
- 磁盘空间 ≥ 2GB（瓦片数据约 500MB-1GB，字体约 100MB）

## 部署步骤

### 1. 准备矢量瓦片数据

```powershell
cd tileserver
.\prepare-data.ps1
```

脚本会自动完成：
1. 下载中国区域 OSM PBF（~1.5GB，首次）
2. 按 `-Cities` 指定的城市（默认苏州）裁剪各市 bbox（使用 osmium）
3. 为每个城市生成 `{key}.mbtiles` 矢量瓦片（使用 tilemaker，约 5-15 分钟/城市）
4. 合并进 `config.json` 的 `data` 段，并把 dark 样式源指向 `-Primary` 城市

**默认输出**：`tileserver/data/suzhou.mbtiles`

> 已有中国 PBF 时可跳过下载：`.\prepare-data.ps1 -SkipDownload`
>
> 支持的城市 key 见 `src/features/offline-map/cities.json`（直辖市 + 省会 + 计划单列市 + 江苏/浙江全域，共 60+ 城市）。
> 多城市示例：`.\prepare-data.ps1 -Cities suzhou,beijing,shanghai`

### 2. 准备中文字体

```powershell
.\prepare-fonts.ps1
```

脚本会自动完成：
1. 下载 Noto Sans + Noto Sans CJK SC 字体
2. 生成 pbf 字体切片
3. 组合 fontstack

**输出**：`tileserver/fonts/Noto Sans Regular/` 目录

### 3. 启动瓦片服务

```powershell
docker compose up -d
```

验证服务状态：
```powershell
# 健康检查
curl http://localhost:8081/health

# 查看可用样式列表
curl http://localhost:8081/styles.json
```

浏览器访问 `http://localhost:8081/styles/dark/` 查看底图渲染效果。

### 4. 配置前端连接

在项目根目录创建 `.env.local`：

```env
# 指向本地瓦片服务（默认 8081 端口，避免与现有 uav-task-server 冲突）
VITE_MAPLIBRE_STYLE_URL=http://localhost:8081/styles/dark/style.json

# 卫星底图样式 URL（默认本地 satellite.mbtiles 栅格源 + gcs-cache 离线缓存，见下方"卫星影像底图"）
# VITE_MAPLIBRE_SATELLITE_STYLE_URL=http://localhost:8081/styles/satellite/style.json

# 部署到其他机器时，替换为瓦片服务器 IP
# VITE_MAPLIBRE_STYLE_URL=http://192.168.1.100:8081/styles/dark/style.json
```

重启前端开发服务器：
```powershell
npm run dev
```

在 UI 中通过 **引擎切换按钮** 切换到 MapLibre，即应看到离线暗色底图。

1. 用最新 OSM 数据重新运行 `prepare-data.ps1`
2. 重启服务：`docker compose restart`

### 自定义样式

编辑 `tileserver/styles/dark/style.json`：
- 修改颜色：调整各 layer 的 `paint` 属性
- 新增图层：参照 [MapLibre Style Spec](https://maplibre.org/maplibre-style-spec/)
- 修改后无需重启，浏览器刷新即可生效

### 卫星影像底图

前端支持通过右下角"图层"按钮在**矢量暗色**与**卫星影像**底图间切换（仅 MapLibre 引擎）。卫星样式定义于 `tileserver/styles/satellite/style.json`，已注册到 `config.json`。

#### 架构：本地栅格源 + 浏览器端缓存（统一缓存流程，严格离线）

卫星样式 `source.url` 指向本地 tileserver-gl 栅格数据源 `mbtiles://satellite.mbtiles`，**与矢量瓦片完全统一、无任何在线回源**。运行时 `transformRequest` 将 tileserver 注入的绝对 origin 重写为 `/tiles` 同源代理路径，并包装为 `gcs-cache://` 自定义协议，走与矢量瓦片完全一致的缓存流程：

| 状态 | 行为 |
|------|------|
| **已下载（IndexedDB 命中）** | 零网络返回缓存瓦片（断网也能看） |
| **未下载（无论联网与否）** | 严格离线：栅格瓦片返回灰色占位、矢量瓦片抛错，**绝不在线回源**任何 tileserver / 在线瓦片服务 |

用户通过 **系统配置 → 下载离线地图** 预取目标区域 / 层级的卫星瓦片到浏览器 IndexedDB，之后无论联网与否均优先本地渲染。卫星底图**不依赖任何在线栅格服务**（无 Esri 等在线兜底）。

#### 准备卫星影像数据

卫星源对应 `tileserver/data/satellite.mbtiles`。仓库内置一个**占位 mbtiles**（仅 1 个灰色 z0 瓦片，约 16KB），由 `tileserver/bin/make-satellite-placeholder.py`（纯 Python 标准库）生成，保证 tileserver-gl 健康启动（不引用不存在的 mbtiles，否则 crash loop）。

**替换为真实卫星数据（离线）**：卫星影像须由运维离线准备，本系统**不提供任何在线抓取能力**（无 Esri 等在线兜底）。用 `tileserver/bin/prepare-satellite.py` 将自有影像（国产高分、无人机正射、公开遥感 GeoTIFF 等）打包为 `satellite.mbtiles`，覆盖占位文件后重启 tileserver 生效。

```powershell
# 方式一：从自有 GeoTIFF 切片并打包（需 GDAL，gdal2tiles）
python tileserver/bin/prepare-satellite.py --input imagery.tif --zoom 10-16

# 方式二：已有 gdal2tiles / rio-tiler 切好的瓦片目录（{z}/{x}/{y}.png），直接打包
python tileserver/bin/prepare-satellite.py --tiles-dir ./tiles --zoom 10-16

# 指定输出路径 / 覆盖重建
python tileserver/bin/prepare-satellite.py --tiles-dir ./tiles --out tileserver/data/satellite.mbtiles --force

# TMS 布局目录（gdal2tiles 旧版默认）需显式声明 --layout tms
python tileserver/bin/prepare-satellite.py --tiles-dir ./tiles --layout tms
```

完成后重启 tileserver：`cd tileserver; docker compose restart`。前端「下载离线地图 → 卫星影像」即可正常预取瓦片到 IndexedDB。

> ⚠️ `--tiles-dir` 模式仅依赖 Python 标准库；`--input` 模式需安装 GDAL（含 `gdal2tiles`）。两种模式均**不联网**。请确保自有影像已取得合法授权并按需署名（可用 `--attribution` 写入 mbtiles metadata）。

> ⚠️ tileserver-gl v5.x 要求 config.json 引用的 mbtiles 必须存在，否则启动时 `ENOENT` crash loop，影响**所有**功能（含矢量地图）。占位文件正是为此兜底。

#### 代理配置

无需为卫星瓦片单独配置代理——卫星与矢量瓦片共用同一 `/tiles` 同源代理（开发环境 Vite proxy、生产环境 Nginx `location /tiles/`），统一转发到本地 tileserver-gl。详见上文「架构概览」。

#### 备注

- `tileserver/config.json` 的 `data.satellite` 段已注册栅格源（format: png）。`/data.json` 会同时返回 `satellite`(png) 与 `suzhou`(pbf)，前端据此区分矢量源与栅格源。
- 占位 mbtiles 仅含 z0，z1+ 瓦片请求返回 404（gcs-cache 协议严格离线：未命中返回灰色占位，不影响使用）。

> 数据体积大，离线卫星数据准备**非自动化**，需按目标区域单独处理。

### 更换 / 增加区域数据（多城市）

数据准备脚本以 `src/features/offline-map/cities.json` 为**单一数据源**：每个城市含
拼音 `key` + 中文 `name` + 市域 `bbox`。前端下载下拉框与数据准备脚本共用此文件，
**新增城市只需编辑 cities.json 一处**（前端立即识别，脚本按 key 取 bbox）。

```powershell
# 默认仅准备苏州（与旧用法兼容）
.\prepare-data.ps1 -SkipDownload

# 批量准备多个城市（每个城市生成独立 {key}.mbtiles 并注册到 config.json）
.\prepare-data.ps1 -Cities suzhou,beijing,shanghai -SkipDownload

# 指定主视图城市（dark 样式渲染该城市；默认取列表第一项）
.\prepare-data.ps1 -Cities nanjing -Primary nanjing -MaxZoom 16
```

脚本会自动：
1. osmium 裁剪各市 bbox（strategy=smart 保留引用完整性）；
2. tilemaker 生成 `{key}.mbtiles`；
3. **合并**进 `config.json` 的 `data` 段（保留已有源），更新各 style 的 bounds 为所选城市并集；
4. 把 dark 样式源指向 `-Primary` 城市的 mbtiles（保证下载该城市瓦片后可离线查看）。

完成后重启服务：`docker compose restart`，并校验 `curl http://localhost:8081/data.json`
应列出全部已注册城市源。

> **与前端下载页的联动**：前端「下载离线地图」会在挂载时探测 `/data.json`，只把
> **已注册（已准备数据）**的城市显示为可选，未准备的城市灰显并标注「未准备数据」。
> 因此：**没有在此脚本准备过的城市，不会出现在下载下拉框，也无法成功下载**。
> 选中一个已准备的城市后，矢量瓦片按 `/tiles/data/{key}/{z}/{x}/{y}.pbf` 入库，
> 运行时离线渲染读取同一键空间，断网后可直接查看该主视图城市。

## 常见问题

### Q: 地图空白 / 瓦片加载失败？("Failed to fetch (0)")

**检查清单**：
1. tileserver 是否运行：`curl http://localhost:8081/health`
2. `.env.local` 中 URL 是否正确
3. 浏览器开发者工具 Network 标签查看 404 请求
4. mbtiles 文件是否存在于 `data/` 目录

> **典型场景**：浏览器控制台报 `Failed to fetch (0): http://localhost:8081/styles/dark/style.json`，
> 但宿主机 `curl http://localhost:8081/styles/dark/style.json` 正常返回 200。
>
> **根因**：Vite 开发服务器配置了 `server.host: true`（绑定 `0.0.0.0`），便于
> 局域网联调。此时若通过 LAN IP（如 `http://192.168.x.x:5173`）或 IPv6
> 访问页面，浏览器会向**客户端自身**的 `localhost:8081` 发起请求，自然无法
> 连接到宿主机的 tileserver-gl。
>
> **内置解决方案**：项目已在 `vite.config.ts` 配置 dev-server 代理
> （`/tiles → http://localhost:8081`），并在 `MapLibreContainer` 中通过
> `transformRequest` 在开发环境自动将瓦片请求重写到同源代理路径。**无需
> 任何额外配置**，浏览器通过任意地址访问页面均可正常加载地图。生产构建
> （`vite build`）不受影响，直接使用环境变量中的绝对 URL。

### Q: 控制台报 `Bad Gateway (502): /tiles/styles/.../style.json`？

**现象**：前端报 `AJAXError: Bad Gateway (502): /tiles/styles/satellite/style.json`，
但直接 `curl http://localhost:8081/styles/satellite/style.json` 返回 200。

**根因**：Windows + Docker Desktop（WSL2 后端）环境下，`wslrelay.exe` 会抢占
`[::1]:8081`（IPv6 回环）。Vite dev-server 代理（Node.js 的 `http-proxy`）
在解析 `localhost` 时常优先命中 IPv6 `::1`，于是把请求转发给了 WSL 端口中继
`wslrelay.exe` 而非 Docker 在 `0.0.0.0:8081` 的真实监听，`wslrelay` 无法转发
即返回 502 Bad Gateway。

**解决**：项目 `vite.config.ts` 已将 `server.proxy` / `preview.proxy` 的 target
固定为 **`http://127.0.0.1:8081`（IPv4 显式地址）**，强制命中 Docker 的
`0.0.0.0:8081` 监听，绕开 `wslrelay` 的 IPv6 抢占。无需手动处理。

手动验证：
```powershell
# 确认谁在监听 8081
netstat -ano | findstr ":8081"
# 若看到 wslrelay.exe 抢占 [::1]:8081，说明命中此问题
tasklist /FI "PID eq <上面的PID>"
```

生产部署（Nginx）同理：`proxy_pass` 应使用 `http://127.0.0.1:8081/;` 而非
`http://localhost:8081/;`。

### Q: 地图一直显示"加载中"，且控制台无报错？

**原因**：Vite 依赖预打包（dep optimizer）会破坏 `maplibre-gl` 的 Web Worker（`maplibre-gl-worker.mjs`）引用，导致 worker 加载失败，`map.on('load')` 永不触发。

**解决**：项目 `vite.config.ts` 已通过以下配置规避，无需手动处理：

```ts
optimizeDeps: { exclude: ['maplibre-gl'] },
worker: { format: 'es' },
```

若更换依赖版本后再次出现该问题，可删除 `node_modules/.vite` 缓存后重启：

```powershell
Remove-Item -Recurse -Force node_modules\.vite
npm run dev
```

### Q: 中文标注不显示（方框/乱码）？

**原因**：字体 pbf 缺失或不匹配。

**解决**：
1. 确认 `tileserver/fonts/Noto Sans Regular/` 目录存在且有 `.pbf` 文件
2. 确认 `style.json` 中 `text-font` 为 `["Noto Sans Regular"]`
3. 重新运行 `.\prepare-fonts.ps1`

### Q: 瓦片数据覆盖范围不够？

**原因**：默认仅裁剪苏州区域。

**解决**：修改 `prepare-data.ps1` 中的 bbox 或提供 `.poly` 边界文件。

### Q: 如何完全离线迁移到另一台机器？

1. 在有网机器上完成步骤 1-2（准备数据 + 字体）
2. 复制整个 `tileserver/` 目录到目标机器
3. 目标机器仅需 Docker，运行 `docker compose up -d`
4. 配置前端 `.env.local` 指向目标机器 IP
