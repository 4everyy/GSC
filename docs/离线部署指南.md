# 离线地图部署指南（方案 A - MapLibre + tileserver-gl）

## 概述

本指南说明如何在内网（无互联网）环境下部署本地矢量瓦片服务，让 MapLibre 地图完全离线运行。

## 架构

```
浏览器 (GCS 前端)
    │
    │ HTTP 请求 Style JSON + Vector Tiles (.pbf) + Glyphs (.pbf)
    ▼
tileserver-gl (Docker, 端口 8081)
    │
    ├── data/suzhou.mbtiles    ← 矢量瓦片数据
    ├── styles/dark/style.json ← 暗色样式定义
    └── fonts/                 ← 中文字体切片
```

## 前置条件

- **Docker Desktop**（Windows 11）已安装并运行
- **网络连接**（仅首次准备数据/字体时需要）
- 磁盘空间 ≥ 2GB（瓦片数据约 500MB-1GB，字体约 100MB）

## 部署步骤

### 1. 准备矢量瓦片数据

```powershell
cd tileserver
.\prepare-data.ps1
```

脚本会自动完成：
1. 下载中国区域 OSM PBF（~500MB，首次）
2. 裁剪苏州区域（使用 osmium）
3. 生成 mbtiles 矢量瓦片（使用 tilemaker，约 10 分钟）

**输出**：`tileserver/data/suzhou.mbtiles`

> 如果已有 PBF 文件，可跳过下载：`.\prepare-data.ps1 -SkipDownload -PbfFile your-file.osm.pbf`

### 2. 准备中文字体

```powershell
.\prepare-fonts.ps1
```

脚本会自动完成：
1. 下载 Noto Sans + Noto Sans CJK SC 字体
2. 生成 pbf 字体切片
3. 组合 fontstack

**输出**：`tileserver/fonts/Noto Sans Regular/` 目录

### 3. 启动瓦片服务

```powershell
docker compose up -d
```

验证服务状态：
```powershell
# 健康检查
curl http://localhost:8081/health

# 查看可用样式列表
curl http://localhost:8081/styles.json
```

浏览器访问 `http://localhost:8081/styles/dark/` 查看底图渲染效果。

### 4. 配置前端连接

在项目根目录创建 `.env.local`：

```env
# 指向本地瓦片服务（默认 8081 端口，避免与现有 uav-task-server 冲突）
VITE_MAPLIBRE_STYLE_URL=http://localhost:8081/styles/dark/style.json

# 卫星底图样式 URL（默认 Esri 在线；离线替换见下方"卫星影像底图"）
# VITE_MAPLIBRE_SATELLITE_STYLE_URL=http://localhost:8081/styles/satellite/style.json

# 部署到其他机器时，替换为瓦片服务器 IP
# VITE_MAPLIBRE_STYLE_URL=http://192.168.1.100:8081/styles/dark/style.json
```

重启前端开发服务器：
```powershell
npm run dev
```

在 UI 中通过 **引擎切换按钮** 切换到 MapLibre，即应看到离线暗色底图。

## 运维操作

### 查看日志
```powershell
docker compose logs -f tileserver
```

### 重启服务
```powershell
docker compose restart tileserver
```

### 停止服务
```powershell
docker compose down
```

### 更新瓦片数据
1. 用最新 OSM 数据重新运行 `prepare-data.ps1`
2. 重启服务：`docker compose restart`

### 自定义样式

编辑 `tileserver/styles/dark/style.json`：
- 修改颜色：调整各 layer 的 `paint` 属性
- 新增图层：参照 [MapLibre Style Spec](https://maplibre.org/maplibre-style-spec/)
- 修改后无需重启，浏览器刷新即可生效

### 卫星影像底图

前端支持通过右下角"图层"按钮在**矢量暗色**与**卫星影像**底图间切换（仅 MapLibre 引擎）。卫星样式定义于 `tileserver/styles/satellite/style.json`，已注册到 `config.json`。

#### 在线模式（默认，需联网）

开箱即用：`satellite/style.json` 默认指向 Esri World Imagery 在线瓦片，有互联网即可直接切换查看。适用于开发演示。

#### 完全离线模式

卫星影像属于**栅格瓦片**，需额外准备 raster mbtiles，流程与矢量瓦片完全不同：

1. **获取数据**：用第三方工具（如 [TilePlus CP](https://github.com/Tilenus/TilePlus-CP)、`satellite-image-downloader`）下载目标区域的卫星瓦片（z3-z16，苏州全境约 5-20GB），导出为 `satellite.mbtiles`
2. **放入数据目录**：`tileserver/data/satellite.mbtiles`
3. **修改样式**：编辑 `tileserver/styles/satellite/style.json`，将 `sources.satellite.tiles` 替换为本地服务：

   ```json
   {
     "sources": {
       "satellite": {
         "type": "raster",
         "tiles": [
           "http://localhost:8081/data/satellite/{z}/{x}/{y}.png"
         ],
         "tileSize": 256,
         "maxzoom": 16
       }
     }
   }
   ```

4. **重启服务**：`docker compose restart`
5. **验证**：`curl http://localhost:8081/data/satellite/12/3372/1698.png -o test.png`，确认返回有效 PNG

> 数据体积大，离线卫星数据准备**非自动化**，需按目标区域单独处理。

### 更换区域数据

1. 准备目标区域的 PBF 文件
2. 运行：`.\prepare-data.ps1 -SkipDownload -PbfFile region.osm.pbf -OutputName region.mbtiles`
3. 修改 `tileserver/config.json` 中的 `data` 和 `styles` 指向新 mbtiles
4. 重启服务

## 常见问题

### Q: 地图空白 / 瓦片加载失败？

**检查清单**：
1. tileserver 是否运行：`curl http://localhost:8081/health`
2. `.env.local` 中 URL 是否正确
3. 浏览器开发者工具 Network 标签查看 404 请求
4. mbtiles 文件是否存在于 `data/` 目录

### Q: 地图一直显示"加载中"，且控制台无报错？

**原因**：Vite 依赖预打包（dep optimizer）会破坏 `maplibre-gl` 的 Web Worker（`maplibre-gl-worker.mjs`）引用，导致 worker 加载失败，`map.on('load')` 永不触发。

**解决**：项目 `vite.config.ts` 已通过以下配置规避，无需手动处理：

```ts
optimizeDeps: { exclude: ['maplibre-gl'] },
worker: { format: 'es' },
```

若更换依赖版本后再次出现该问题，可删除 `node_modules/.vite` 缓存后重启：

```powershell
Remove-Item -Recurse -Force node_modules\.vite
npm run dev
```

### Q: 中文标注不显示（方框/乱码）？

**原因**：字体 pbf 缺失或不匹配。

**解决**：
1. 确认 `tileserver/fonts/Noto Sans Regular/` 目录存在且有 `.pbf` 文件
2. 确认 `style.json` 中 `text-font` 为 `["Noto Sans Regular"]`
3. 重新运行 `.\prepare-fonts.ps1`

### Q: 瓦片数据覆盖范围不够？

**原因**：默认仅裁剪苏州区域。

**解决**：修改 `prepare-data.ps1` 中的 bbox 或提供 `.poly` 边界文件。

### Q: 如何完全离线迁移到另一台机器？

1. 在有网机器上完成步骤 1-2（准备数据 + 字体）
2. 复制整个 `tileserver/` 目录到目标机器
3. 目标机器仅需 Docker，运行 `docker compose up -d`
4. 配置前端 `.env.local` 指向目标机器 IP

## 性能参考

| 指标 | 参考值 |
|------|--------|
| 首次加载体积 | ~200KB（样式+字体+首屏瓦片） |
| 单瓦片大小 | 10-50KB（gzip 压缩后） |
| tileserver 内存 | ~200MB |
| 并发支持 | 单实例约 100+ 并发 |
