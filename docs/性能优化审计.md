## 二、优化机会清单（按优先级）

### P1 处理结果（2026-09-19）

#### O1. 每条 WS 下行消息 `JSON.parse` 两次 —— ✅ 已修复
- **位置**：`wsClient.ts` onmessage：`logDownlinkFrame(event.data)` 内部 `JSON.parse(raw)` 打印日志，`dispatch(event.data)` 再 parse 一次做校验分发
- **修复**：日志打印移入 `dispatch()`——parse 成功后直接把已解析对象传给 `logDownlinkFrame(parsed)`，全链路只 parse 一次（见 `logDownlinkFrame` 函数注释）。行为完全等价（原实现日志分支 parse 失败时打印原文，但 parse 失败的消息在 dispatch 中本就被丢弃，无观测损失）

#### O2. HomePage 订阅整表 `s.devices` + 8 套 rAF 动画每帧写 store —— ❌ 核实不成立（审计误判，关闭）
- **核实证据**：
  1. `src/stores/index.ts` 的 `flightAnimStore` 注释明确记录：8 组飞行状态已自 `useFlightAnimations` 的 useState **迁出至专用 Zustand store**，rAF tick 只重渲染订阅了对应状态的叶子覆盖层组件
  2. `useFlightAnimations.ts` 实测：全部 rAF 循环通过 `useFlightAnimStore.getState().setXxx()` 写入（getState 直调，不经 React 渲染）
  3. 订阅者仅 `FlightOverlays.tsx` / `FlightSimulationOverlays.tsx` 两个叶子覆盖层（按 selector 订阅各自切片），HomePage 不订阅任何动画状态
  4. `usePlaneStatusStore((s) => s.devices)`（HomePage/DeviceManagementPanel）只在 `refresh()` 整体替换时变化，而 `refresh` 仅由 `usePlaneStatusInit` 在 MainApp 挂载时调用一次（模块级 `initialized` 守卫，无轮询），非高频路径
- **结论**：HomePage 与动画 tick 已解耦，无需改造。若未来加入设备状态轮询或 HomePage 订阅 `s.telemetry`，再按原建议评估 per-device selector

### P2（规划处理）

#### O3. wsStore `telemetry` Record 整对象替换
- **位置**：`wsClient.ts` `set({ telemetry: { ...get().telemetry, [id]: t } })`
- **影响**：当前无组件直接订阅 `s.telemetry`（安全）；但未来接入真实渲染时，任何整表订阅都会 N 台 × 5Hz 全量重渲染
- **建议**：接入时统一用 per-device selector 或 zustand `subscribeWithSelector`；在 store 注释中已有约定，建议补 lint/文档强化

#### O4. 大列表无虚拟化
- **位置**：`DeviceManagementPanel`（>20 无限滚动）、`TargetListPanel`（PRD 指标 200 条）、`TaskListPanel`
- **影响**：200 条目标行（含旗子/删除/详情展开）一次性进 DOM，滚动与联动有掉帧风险（对应 TC-TGT-18 ≤200ms 指标）
- **建议**：目标列表优先接入 `content-visibility: auto`（零改造成本，先验证）或 react-window；设备/任务列表按实测数据量决定

#### O5. `TaskPanels.tsx` 806 行巨型组件
- **影响**：五步向导全部状态在一个组件，任一步输入都全组件重渲染（含 20 台设备卡片、航线卡片组）
- **建议**：按步骤拆分子组件 + 各自 memo；数字输入 onChange 局部化。与 TC-TSK-43（20 设备 ≤2s）相关

#### O6. `alarms` 每条告警 `slice(-LIMIT)` 新数组
- **位置**：`wsClient.ts` reducer
- **影响**：告警风暴（TC-ALM-21 高频注入）时每条消息分配新数组；小开销但高频累积
- **建议**：仅在超限时 slice（`length > LIMIT` 才裁剪）；当前写法其实已如此，确认无越界累积即可，属低风险核对项

#### O7. `MainApp`/`MapChrome` 中遗留模拟 Promise（`setTimeout 1500 + Math.random`）
- **位置**：`MapChrome.tsx`
- **影响**：非性能本身，但生产环境应确认被真实接口替换，避免假延迟干扰性能测量
- **建议**：接入真实 API 后移除；构建期可用环境变量隔离 mock
