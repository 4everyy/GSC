## 1. 背景与目标

### 1.1 当前现状

项目当前使用 **百度地图 GL SDK**（`BMapGL`），存在以下公网依赖：

| 依赖项 | 说明 |
|--------|------|
| SDK 脚本加载 | `https://api.map.baidu.com/api?type=webgl&v=3.0&ak=...` |
| 底图瓦片 | 百度 CDN 实时请求栅格/卫星瓦片 |
| 定位服务 | `BMapGL.Geolocation` 依赖百度服务端 |
| 坐标系 | BD09（百度专有偏移坐标系） |

在离线/内网环境下，以上所有公网依赖均不可用，地图功能将完全瘫痪。

### 1.2 目标

- ✅ SDK 完全本地化：前端地图库通过 npm 安装并打包，无 CDN 引用
- ✅ 自建瓦片服务器：在内网部署瓦片服务，浏览器从内网获取地图底图
- ✅ 零公网依赖：整个地图功能可在无外网环境运行
- ✅ 性能达标：支持态势大屏场景，万级图标流畅渲染

## 2. 方案总览

### 2.1 三套候选方案

| 维度 | 方案 A：MapLibre GL JS | 方案 B：Leaflet | 方案 C：OpenLayers |
|------|----------------------|-----------------|-------------------|
| 瓦片类型 | **矢量瓦片（MVT）** | 栅格瓦片 | 矢量 + 栅格 |
| SDK 本地化 | ✅ npm 包，无外部依赖 | ✅ npm 包 | ✅ npm 包 |
| 公网依赖 | ❌ 完全无 | ❌ 完全无 | ❌ 完全无 |
| 渲染方式 | GPU 矢量渲染（WebGL） | DOM / Canvas | Canvas / WebGL |
| 渲染性能 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 3D/倾斜支持 | ✅ 原生支持 | ❌ 需插件 | 有限支持 |
| 样式动态切换 | ✅ 运行时切换 | ❌ 需重新切片 | ✅ |
| 包体积（gzipped） | ~250KB | ~40KB | ~120KB |
| 学习曲线 | 中等 | 低 | 较高 |
| 离线瓦片成本 | 需矢量切片工具链 | 栅格切片，工具成熟 | 两者皆可 |
| 社区生态 | 活跃（MapBox 分叉） | 最成熟 | 成熟 |
| 开源协议 | BSD-3 | BSD-2-Clause | BSD-2-Clause |
| **推荐场景** | **高性能态势大屏** | 轻量快速原型 | 复杂 GIS 分析 |

### 2.2 技术选型决策树

```
是否需要 3D 地形/倾斜视图？
├─ 是 → MapLibre GL JS（方案 A）
└─ 否
   └─ 图标数量级？
      ├─ > 5000 个 → MapLibre GL JS（方案 A）
      └─ < 5000 个
         └─ 是否需要空间分析（量算、缓冲区）？
            ├─ 是 → OpenLayers（方案 C）
            └─ 否 → Leaflet（方案 B）
```

## 3. 方案 A：MapLibre GL JS + 矢量瓦片（首选推荐）

### 3.1 技术架构

```
┌─────────────────────────────────────────────────────┐
│                    内网浏览器                         │
│  ┌─────────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ MapLibre GL │  │ Deck.gl  │  │  React 应用    │  │
│  │  (本地SDK)  │  │ (叠加层) │  │  (业务逻辑)    │  │
│  └──────┬──────┘  └────┬─────┘  └────────────────┘  │
│         │              │                             │
└─────────┼──────────────┼─────────────────────────────┘
          │              │
          ▼              ▼
   ┌──────────────────────────┐
   │    内网瓦片服务器          │
   │  (tileserver-gl / Martin) │
   │  端口: http://内网IP:8080  │
   └──────────┬───────────────┘
              │
              ▼
   ┌──────────────────────────┐
   │  MBtiles / PostGIS 数据库 │
   │  (预切片的地图数据)        │
   └──────────────────────────┘
```

### 3.2 前端集成方式

```bash
npm install maplibre-gl
```

```typescript
import maplibregl from 'maplibre-gl'
import 'maplibre-gl/dist/maplibre-gl.css'

// 初始化地图，所有 URL 指向内网
const map = new maplibregl.Map({
  container: 'map',
  style: {
    version: 8,
    // 矢量瓦片源（内网地址）
    sources: {
      'osm-tiles': {
        type: 'vector',
        tiles: ['http://192.168.1.100:8080/data/v3/{z}/{x}/{y}.pbf'],
        minzoom: 0,
        maxzoom: 14,
      },
      // 栅格瓦片源（卫星图等，可选）
      'satellite-tiles': {
        type: 'raster',
        tiles: ['http://192.168.1.100:8080/data/satellite/{z}/{x}/{y}.png'],
        tileSize: 256,
      },
    },
    // 图层样式定义（本地 JSON 文件）
    layers: [
      {
        id: 'background',
        type: 'background',
        paint: { 'background-color': '#08283b' },
      },
      {
        id: 'water',
        type: 'fill',
        source: 'osm-tiles',
        'source-layer': 'water',
        paint: { 'fill-color': '#0d3b66' },
      },
      // ... 更多图层
    ],
    // 字体和图标（本地托管）
    glyphs: 'http://192.168.1.100:8080/fonts/{fontstack}/{range}.pbf',
    sprite: 'http://192.168.1.100:8080/styles/basic/sprite',
  },
  center: [114.05, 22.55], // WGS84 坐标
  zoom: 12,
})
```

### 3.3 样式管理

矢量瓦片的最大优势是**样式与数据分离**，可运行时动态切换：

```typescript
// 暗色模式（态势大屏）
const darkStyle = await fetch('/styles/dark/style.json').then((r) => r.json())
map.setStyle(darkStyle)

// 卫星模式
const satelliteStyle = await fetch('/styles/satellite/style.json').then((r) => r.json())
map.setStyle(satelliteStyle)
```

常用开源样式：
- **OSM Liberty**：类 Google Maps 风格
- **Dark Matter**：暗色风格（适合大屏）
- **Positron**：浅色极简风格

### 3.4 优势

- ✅ **GPU 矢量渲染**：帧率稳定 60fps，万级图标流畅
- ✅ **运行时样式切换**：暗色/卫星/地形自由切换，无需重新切片
- ✅ **3D 地形**：支持 terrain DEM 高程渲染
- ✅ **Deck.gl 集成**：与高性能可视化库无缝配合
- ✅ **BSD-3 协议**：无商用限制

### 3.5 劣势

- ❌ 矢量切片工具链有一定学习成本
- ❌ 瓦片数据准备需一次性投入
- ❌ 包体积相对较大（~250KB gzipped）

## 4. 方案 B：Leaflet + 栅格瓦片（轻量方案）

### 4.1 技术架构

```
┌─────────────────────────────────────────────────────┐
│                    内网浏览器                         │
│  ┌─────────────┐  ┌──────────────────────────────┐  │
│  │   Leaflet   │  │       React 应用              │  │
│  │  (本地SDK)  │  │       (业务逻辑)              │  │
│  └──────┬──────┘  └──────────────────────────────┘  │
│         │                                             │
└─────────┼─────────────────────────────────────────────┘
          │
          ▼
   ┌──────────────────────────┐
   │    Nginx 静态文件服务器     │
   │  /tiles/{z}/{x}/{y}.png  │
   │  端口: http://内网IP:80   │
   └──────────────────────────┘
```

### 4.2 前端集成方式

```bash
npm install leaflet react-leaflet
npm install -D @types/leaflet
```

```typescript
import L from 'leaflet'
import 'leaflet/dist/leaflet.css'

const map = L.map('map').setView([22.55, 114.05], 12)

// 栅格瓦片层（内网 Nginx 地址）
L.tileLayer('http://192.168.1.100/tiles/{z}/{x}/{y}.png', {
  maxZoom: 18,
  attribution: '© 内网地图服务',
}).addTo(map)

// 添加标记
L.marker([22.55, 114.05]).addTo(map).bindPopup('中心点')
```

### 4.3 大量标记优化

Leaflet 默认使用 DOM 元素渲染标记，数量大时性能急剧下降，需引入聚类插件：

```bash
npm install leaflet.markercluster
```

```typescript
import 'leaflet.markercluster'
import 'leaflet.markercluster/dist/MarkerCluster.css'

const markers = L.markerClusterGroup()
// 批量添加 10000+ 标记
for (const item of data) {
  markers.addLayer(L.marker([item.lat, item.lng]))
}
map.addLayer(markers)
```

### 4.4 优势

- ✅ **最轻量**（~40KB gzipped），加载速度快
- ✅ **API 简洁**，上手最快，社区资源丰富
- ✅ **栅格瓦片通用性高**：任何底图来源（卫星图、地形图）均可切片
- ✅ **Nginx 静态托管**，运维极简

### 4.5 劣势

- ❌ **无 3D/倾斜视图**（需 Leaflet-3D 插件，不成熟）
- ❌ **栅格瓦片无法动态换样式**（换风格需重新切片）
- ❌ **大量标记性能弱**（需聚类插件妥协视觉细节）
- ❌ **与 Deck.gl 集成不便**（坐标系和渲染层不一致）

## 5. 方案 C：OpenLayers + 混合瓦片（全功能方案）

### 5.1 技术架构

```
┌─────────────────────────────────────────────────────┐
│                    内网浏览器                         │
│  ┌─────────────┐  ┌──────────────────────────────┐  │
│  │ OpenLayers  │  │       React 应用              │  │
│  │  (本地SDK)  │  │       (业务逻辑)              │  │
│  └──────┬──────┘  └──────────────────────────────┘  │
│         │                                             │
└─────────┼─────────────────────────────────────────────┘
          │
          ▼
   ┌──────────────────────────────────────┐
   │  内网 GIS 服务器                       │
   │  GeoServer / MapServer / tileserver   │
   │  支持: WMS / WMTS / MVT / 栅格        │
   │  端口: http://内网IP:8080              │
   └──────────────────────────────────────┘
```

### 5.2 前端集成方式

```bash
npm install ol
```

```typescript
import Map from 'ol/Map'
import View from 'ol/View'
import TileLayer from 'ol/layer/Tile'
import VectorTileLayer from 'ol/layer/VectorTile'
import XYZ from 'ol/source/XYZ'
import VectorTileSource from 'ol/source/VectorTile'
import MVT from 'ol/format/MVT'

const map = new Map({
  target: 'map',
  layers: [
    // 栅格底图
    new TileLayer({
      source: new XYZ({
        url: 'http://192.168.1.100:8080/tiles/{z}/{x}/{y}.png',
      }),
    }),
    // 矢量瓦片叠加
    new VectorTileLayer({
      source: new VectorTileSource({
        format: new MVT(),
        url: 'http://192.168.1.100:8080/data/v3/{z}/{x}/{y}.pbf',
      }),
    }),
  ],
  view: new View({
    center: [12694319, 2581069], // EPSG:3857 坐标
    zoom: 12,
  }),
})
```

### 5.3 优势

- ✅ **功能最全**：支持 MVT 矢量 + 栅格 + WMS/WMTS/WCS 全部 OGC 标准
- ✅ **专业 GIS 能力**：测绘量算、缓冲区分析、空间查询
- ✅ **可对接内网 GeoServer**：发布专业 GIS 服务
- ✅ **投影系统灵活**：支持自定义 EPSG 投影

### 5.4 劣势

- ❌ **API 复杂度高**，开发效率相对低
- ❌ **包体积大**（~120KB gzipped）
- ❌ **对态势展示场景功能过剩**，ROI 低
- ❌ **与 Deck.gl 集成需额外适配**

## 6. 离线瓦片服务器选型

### 6.1 服务器对比

| 服务器 | 语言 | 瓦片类型 | 数据源 | 特点 | 适用场景 |
|--------|------|----------|--------|------|----------|
| **tileserver-gl** | Go | 矢量 + 栅格 | MBTiles 文件 | 轻量，开箱即用，自带样式预览 | 快速部署，数据量中等 |
| **Martin** | Rust | 矢量 | PostgreSQL+PostGIS | 高性能，直连数据库 | 实时数据，大数据量 |
| **tegola** | Go | 矢量 | PostGIS / GeoPackage | 灵活，支持多种数据源 | 定制化需求 |
| **GeoServer** | Java | 全格式 | 数据库 / 文件 | 功能最全，支持 WMS/WMTS/WFS | 企业级 GIS 平台 |
| **Nginx（静态）** | - | 栅格 | 文件目录 | 最简，无计算开销 | 栅格瓦片托管 |

### 6.2 推荐配置

**快速验证（POC 阶段）**：
```
tileserver-gl + 预制 MBTiles 文件
→ 单个二进制即可运行，5 分钟内部署完成
```

**生产环境**：
```
Martin + PostgreSQL/PostGIS + PMTiles
→ 数据库统一管理，支持实时更新，高性能
```

### 6.3 tileserver-gl 快速部署示例

```bash
# 下载
docker run -it -v $(pwd):/data -p 8080:8080 \

  --config /data/config.json

    "urls_relative_path": "/"
  },
  "styles": {
    "basic": {
      "style": "styles/basic/style.json",

  "data": {
    "v3": {
      "mbtiles": "data/v3.mbtiles"
    }
  }
```

## 7. 瓦片数据获取与制作

### 7.1 数据源对比

| 数据源 | 类型 | 授权 | 覆盖范围 | 获取方式 |
|--------|------|------|----------|----------|
| **OpenStreetMap** | 矢量 | ODbL（开源） | 全球 | Geofabrik 下载 `.pbf` |
| **OpenMapTiles** | 矢量切片 | CC-BY | 全球 | 预制 MBTiles 下载 |
| **天地图** | 栅格 | 需授权 | 中国 | API 批量下载（注意合规） |
| **本地 GeoTIFF** | 栅格 | 自有 | 自定义 | `gdal2tiles` 切片 |
| **Esri World Imagery** | 栅格卫星 | 需授权 | 全球 | 需购买离线包 |

### 7.2 矢量瓦片制作流程（OpenMapTiles 方案）

```
步骤 1: 下载 OSM 区域数据
        ↓ Geofabrik 下载 .pbf 文件（如 china-latest.osm.pbf，约 1GB）

步骤 2: 切片生成 MBTiles
        ↓ 使用 tilemaker 或 openmaptiles-tools
        ↓ tilemaker --input china.osm.pbf --output china.mbtiles \
        ↓   --config config.json --process process.lua

步骤 3: 托管瓦片服务
        ↓ tileserver-gl 加载 china.mbtiles

步骤 4: 配置样式
        ↓ 引用 OpenMapTiles 开源样式（dark matter / positron / osm-liberty）
```

**预估数据量**：

| 区域范围 | OSM PBF | MBTiles（矢量） | MBTiles（栅格卫星） |
|----------|---------|-----------------|---------------------|
| 深圳市 | ~50MB | ~100MB | ~2GB |
| 广东省 | ~300MB | ~800MB | ~20GB |
| 中国大陆 | ~1.2GB | ~5GB | ~200GB |

### 7.3 栅格瓦片制作流程

```bash
# 使用 GDAL 将 GeoTIFF 切片为 XYZ 瓦片目录
gdal2tiles.py --zoom=8-18 \
  --processes=8 \
  --xyz \
  input.tif \
  /var/www/tiles/

# Nginx 配置
location /tiles/ {
  alias /var/www/tiles/;
  add_header Access-Control-Allow-Origin *;
}
```

## 8. 离线部署关键注意事项

### 8.1 坐标系迁移

| 项目 | 当前（百度） | 离线方案（推荐） |
|------|-------------|-----------------|
| 坐标系 | BD09（百度偏移） | **WGS84 / EPSG:4326**（国际标准） |
| 坐标转换 | `wgs84ToBd09` | 不再需要偏移转换 |
| Web 墨卡托 | 不适用 | **EPSG:3857**（瓦片渲染标准） |

**迁移策略**：项目已有 `coordTransform.ts`，离线方案下无人机/飞行器原始 WGS84 坐标**无需转换**直接使用，简化了数据流。

### 8.2 字体与图标资源

矢量瓦片渲染需要本地托管以下资源：

```
/tileserver/
├── data/
│   └── v3.mbtiles          # 瓦片数据
├── fonts/                   # 字体（pbf 格式）
│   ├── Noto Sans Regular/
│   └── Noto Sans CJK/       # 中文字体（必需）
└── styles/
    └── basic/
        ├── style.json
        └── sprite            # 图标精灵图
```

> ⚠️ **中文字体**：需额外配置 `Noto Sans CJK` 或开源中文字体切片，否则中文标注无法显示。

### 8.3 网络与安全

| 关注点 | 解决方案 |
|--------|----------|
| HTTPS 混合内容 | 瓦片服务必须与前端**同协议**（HTTPS 页面不能请求 HTTP 瓦片） |
| 跨域（CORS） | 瓦片服务器需配置 `Access-Control-Allow-Origin` |
| 端口隔离 | 建议瓦片服务使用独立端口或子域名，通过 Nginx 反向代理统一 |
| 内网 DNS | 配置内网域名（如 `maps.internal`），避免硬编码 IP |

### 8.4 性能调优

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `maxZoom`（矢量） | 14 | 矢量瓦片 14 级以上靠 overzooming 放大 |
| `maxZoom`（栅格） | 18 | 栅格瓦片需预切到 18 级 |
| 缓存策略 | `Cache-Control: max-age=31536000` | 瓦片不变，可长期缓存 |
| Gzip/Brotli | 开启 | `.pbf` 矢量瓦片压缩率 > 70% |
| HTTP/2 | 开启 | 多路复用加速瓦片并发请求 |

## 9. 与现有项目的兼容性分析

### 9.1 需要替换的模块

| 现有模块 | 替换为 | 改动量 |
|----------|--------|--------|
| `loadBMapGL.ts` | `loadMapLibreGL.ts`（或直接 import） | 小 |
| `BMapContainer.tsx` | `MapLibreContainer.tsx` | 大（API 重写） |
| `coordTransform.ts` | 移除 BD09 转换，保留 WGS84→EPSG:3857 | 中 |
| `config/map.ts` | 更新坐标系和瓦片源配置 | 小 |
| `types/bmap.d.ts` | 安装 `maplibre-gl` 自带类型 | 小 |

### 9.2 可复用的模块

- ✅ `BMapContainer.css`：容器布局样式可复用
- ✅ 航线/航点数据模型：`types.ts` 中的坐标类型改为 WGS84 即可
