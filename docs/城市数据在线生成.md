# 城市数据在线生成（管理后端服务）

## 背景

「地图切换」Tab 允许用户切换矢量城市数据源（苏州 / 南京 / …）。已准备数据的城市
（mbtiles 已注册到 tileserver-gl）可直接切换；**未准备数据的城市**以往需运维手动在
服务端运行 `prepare-data.ps1`。本后端服务让前端能**在线触发**该生成流程，并以进度条
实时展示，生成完毕自动重启 tileserver-gl 并切换地图。

> 设计依据：方案 A「城市不固定 + 运行时生成」需求。城市清单来自
> `src/features/offline-map/cities.json`（前后端单一数据源，新增城市只需编辑此文件）。

## 架构

```
浏览器（地图切换 Tab）
  用户选中「未准备数据」的城市 → 弹确认
    │ POST /api/admin/prepare  { city }
    ▼
server/index.mjs（Express，监听 127.0.0.1:8082）
  ├─ 鉴权（Bearer Token）
  ├─ spawn powershell prepare-data.ps1 -Cities <city>
  ├─ 逐行读 stdout → 阶段化进度
  └─ 进程退出码 0 → docker compose restart
        │
        ▼
tileserver-gl 重载 config.json（含新城市 mbtiles）
```

## 部署步骤

### 1. 配置令牌

复制令牌样板并填写：

```powershell
copy server\.env.example server\.env
# 编辑 server/.env，把 GCS_ADMIN_TOKEN 改为一个足够长的随机串
```

同时在前端项目根目录创建 `.env`（或追加），填入**相同**的令牌：

```
VITE_ADMIN_TOKEN=change-me-to-a-long-random-string
```

> 令牌用于鉴权管理 API。后端未配置时 fail-closed（拒绝一切管理操作）。
> 前端 `import.meta.env.VITE_ADMIN_TOKEN` 在构建期注入，与后端 `GCS_ADMIN_TOKEN` 必须一致。

### 2. 启动后端服务

```powershell
# 开发（文件改动自动重启）
npm run server:dev

# 生产（PM2 守护）
npm install -g pm2
pm2 start server/index.mjs --name gcs-admin
pm2 save
pm2 startup   # 开机自启
```

服务仅监听 `127.0.0.1:8082`，由 vite dev proxy 或生产 Nginx 同机反代访问：

```nginx
# Nginx 生产配置
location /api/ {
    proxy_pass http://127.0.0.1:8082;
    proxy_set_header Host $host;
}
```

### 3. 前端代理（已配置）

`vite.config.ts` 的 `server.proxy` 与 `preview.proxy` 已含：

```ts
'/api': { target: 'http://127.0.0.1:8082', changeOrigin: true }
```

开发环境前端 `/api/admin/*` 请求自动转发到后端，无需额外配置。

## 使用流程

1. 启动 tileserver-gl（`docker compose up -d`）与后端服务（`npm run server`）。
2. 前端「地图切换」Tab → 城市下拉框，已准备的城市正常可选，未准备的标注「（未准备数据）」。
3. 选中未准备城市 → 弹出确认框「立即生成」→ 进度弹窗实时显示：
   - 百分比进度条（里程碑：环境检查 3% → 下载 8% → 裁剪 26% → tilemaker 42-88% → 注册 88% → 重启 95-100%）
   - 当前阶段、已耗时、最近 30 行实时日志
4. 生成完成（约 5-15 分钟/城市，首次需下载 1.5GB PBF）→ 自动重启 tileserver-gl → 切换到该城市。

## 运行约束

- **WSL 依赖**：`prepare-data.ps1` 依赖 WSL 中的 `osmium-tool` 与 `tilemaker`，因此后端
  服务**必须运行在装了 WSL 的 Windows 宿主机上**，不能放进 Docker 容器。
- **单任务并发**：同一时刻只允许一个生成任务（避免重复下载 PBF + tilemaker 抢 CPU）。
  第二个请求返回 `409 busy`，前端自动转去轮询现有任务进度。
- **docker restart 副作用**：生成完毕会 `docker compose restart` tileserver-gl，期间
  （约 3-5 秒）所有用户的瓦片请求会短暂中断。前端在 done 后延迟 3 秒再切换，留出重载时间。
- **首次下载**：第一个城市首次生成需下载 1.5GB 中国 PBF（耗时取决于网速）；后续城市
  复用已下载的 PBF，仅需 osmium 裁剪 + tilemaker 切片。

## API

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/health` | 无 | 健康检查，返回 `{ ok: true }` |
| POST | `/api/admin/prepare` | Bearer | 触发生成，body `{ city, primary?, maxZoom? }`，返回 `{ status: 'running'|'busy', jobId }` |
| GET | `/api/admin/jobs/current` | Bearer | 查询当前任务进度快照（前端轮询） |

## 故障排查

- **前端提示「无法启动生成」**：后端服务未启动，或令牌不匹配。检查 `npm run server` 日志
  与 `VITE_ADMIN_TOKEN` / `GCS_ADMIN_TOKEN` 是否一致。
- **进度卡在某阶段**：tilemaker 阶段最久（5-15 分钟）属正常；若长时间无变化，查看后端
  控制台是否有 WSL / docker 错误。
- **生成完成但地图仍空白**：tileserver-gl 重启较慢，或 `config.json` 合并异常。手动
  `curl http://localhost:8081/data.json` 确认新城市已注册。
